# Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four card faces, a four-color deck switch, six card back patterns in the existing five colors, and settings rows with a live preview.

**Architecture:** `CardFaceView` and `CardBackView` read the new per-device settings from `@AppStorage` themselves, so every caller (board, hole cards, ranking, settings) follows a change at once, also while a table is open. Both take an optional override so the settings pickers can draw one specific face or pattern. Suit colors come from theme tokens; the `solid` face's fills are fixed and ignore the theme.

**Tech Stack:** SwiftUI, iOS 17, Swift 6 language mode. No assets, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-16-themes-and-cards-design.md`, section "PR 2: cards" plus the card lines in "Decisions made while writing". Reference image: `docs/superpowers/specs/images/2026-11-16-cards.jpg`. Proportions below come from the mockup's CSS (`.superpowers/brainstorm/79585-1794858420/content/cards-final.html`, local), drawn there at widths 84 and 50.

## Global Constraints

- App-only. `Sources/PokerCore`, `Sources/PokerNet`, `Sources/PokerSession` and the wire protocol are not touched.
- iOS 17 deployment target. Swift 6 language mode; fix concurrency errors, do not silence them.
- Everything is drawn in code: shapes, gradients, `Canvas`, font glyphs. No image assets.
- New settings are per device, never synced: `@AppStorage("cardFace")` default `classic`, `@AppStorage("fourColorDeck")` default `false`, `@AppStorage("cardBackPattern")` default `medallion`. `@AppStorage("cardBack")` keeps its key, its five colors and default `red`.
- Card proportions stay as in `CardShape`: 5:7, corner radius `0.12 w`.
- VoiceOver labels do not change. Face-down cards stay `accessibilityHidden`.
- Nothing about cards goes over the wire. The monogram is the device owner's own letter.
- Code, comments and commits in English. Conventional Commits, scope `app`.
- New files under `App/Sources` need `xcodegen generate --spec App/project.yml` and nothing else.
- Carry existing `ponytail:` comments along when editing the code they sit on.
- Work on branch `feat/cards`, created from `main`.

## Review Focus

1. **"10" at the smallest board width.** On an iPhone SE the board card is `0.085` of a 303-point table, about 26 points, narrower than the mockup's 32. Expected: "10" is readable and does not touch the big suit in every face. Pinned in Task 1, step 4.
2. **Settings changed while a table is open.** Settings open from the table. Expected: board, hole cards and seat labels switch face, four-color and back at once, with no stale card. Pinned in Task 3, step 3.
3. **Monogram from an odd name.** Names may start with a space, a lowercase letter, `ß` (uppercases to "SS"), an emoji, or be empty. Expected: one glyph that fits inside the gold frame; a spade when the trimmed name is empty. Pinned in Task 2, steps 1 and 4.
4. **Four-color on Neon dark's dark face.** Expected: diamonds `6aa5ff` and clubs `4cc47a` read on `232a3a`; the `solid` face ignores the theme. Pinned in Task 1, step 4.
5. **Drop shadow cut off.** `CardShape` clips; a shadow inside the clip vanishes, and one on the board slot doubles up. Expected: a soft shadow on faces and backs at every size, none on the empty slot. Pinned in Task 1, step 4 and Task 2, step 4.

| Pattern | Drawing | Frame |
|---|---|---|
