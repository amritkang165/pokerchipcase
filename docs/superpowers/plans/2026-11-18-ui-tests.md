# UI Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local XCUITest target that audits the main screens in every theme and brightness, checks the name field limit and the hole-cards label, and keeps a screenshot per state.

**Architecture:** One UI test target, `PokerChipCaseUITests`, defined in `App/project.yml` with sources in `App/UITests/`. A launch helper starts the app in a game state through the existing debug launch arguments. A settings helper switches theme and brightness through the Settings sheet, so the slow debug table starts once per game state. Audit findings that exist today go on an ignore list; each entry names its GitHub issue.

**Tech Stack:** Swift 6, XCTest/XCUITest (`performAccessibilityAudit`, iOS 17), xcodegen 2.47, Xcode 27, `xcrun xcresulttool`.

**Spec:** [docs/superpowers/specs/2026-11-18-ui-tests-design.md](../specs/2026-11-18-ui-tests-design.md)

## Global Constraints

- Swift 6 language mode (`SWIFT_VERSION: "6.0"`); fix concurrency errors instead of silencing them. `XCUIApplication` is main-actor isolated, so test classes are `@MainActor`.
- UI tests use XCTest, not Swift Testing; Swift Testing cannot drive UI. AGENTS.md states this exception.
- Every launch passes `-AppleLanguages (en) -AppleLocale en_US`.
- A test that switches theme or brightness in the Settings sheet never passes `-theme` or `-appearance`: a launch argument wins over what the sheet writes.
- No fixed sleeps. Wait with `waitForExistence(timeout:)` or an `XCTNSPredicateExpectation`, and fail with a message that names the state that was not reached.
- No app changes beyond accessibility identifiers.
- Local only: no CI job, no change to `.github/workflows`.
- Simulator: `SE3 test` (iPhone SE 3rd generation). Create it with `xcrun simctl create "SE3 test" "iPhone SE (3rd generation)"` if missing.
- The UI test command, used in every task's verification:

  ```sh
  rm -rf .build/uitests/UITests.xcresult
  xcodebuild test -project App/PokerChipCase.xcodeproj -scheme PokerChipCase -destination 'platform=iOS Simulator,name=SE3 test' -derivedDataPath .build/uitests -resultBundlePath .build/uitests/UITests.xcresult -quiet
  ```

- Screenshot export: `xcrun xcresulttool export attachments --path .build/uitests/UITests.xcresult --output-path .build/uitests/attachments`.
- Code, comments, docs and commits in English; Conventional Commits; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A saved game left by an earlier table test: the clean start-screen sweep must still pass when it runs after a table test. Pinned in Task 3, Step 4.
2. A theme pick that does not take effect (for example because a launch argument overrides it): the sweep must fail instead of auditing the old theme eight times. Pinned in Task 3 by asserting the picker's value after each pick.
3. A debug table that never reaches its stop (slow bots, a bot error): the test must fail within its timeout with a message, not hang. Pinned in Task 2, Step 1.
4. A name field that already holds text from an earlier run: the test must clear it before typing. Pinned in Task 1, Step 1 (the expected value is exact).
5. A simulator in a German locale: chip counts must read "1,000", not "1.000". Pinned in Task 2, Step 1.

### Task 2: Debug table states and the hole-cards label

**Implementer:** sonnet medium.

**Files:**

- Modify: `App/UITests/AppLaunch.swift` (wait helper)
- Create: `App/UITests/TableTests.swift`
- Modify: `App/Sources/CardViews.swift:224` (identifier on `HoleCardsView`)

**Interfaces:**

- Consumes: `XCUIApplication.launched(…)` from Task 1.
- Produces: `extension XCUIApplication { func waitForTableStop(_ stop: String, timeout: TimeInterval = 120) }`, which fails the test with `"table did not reach stop <stop>"` when the timeout passes. Supported stops: `turn` (the host's own turn: the Fold button is enabled) and `payout` (a digital game after its first paid-out showdown). Task 3 uses both.
- Produces: accessibility identifier `holeCards` on `HoleCardsView`.

- [ ] **Step 1: Write the failing tests** in `TableTests.swift`:

```swift
@MainActor
final class TableTests: XCTestCase {
    func testHiddenHoleCardsReadAsHidden() {
        let app = XCUIApplication.launched(debugTable: true, stop: "turn", digitalCards: true)
        app.waitForTableStop("turn")
        let cards = app.descendants(matching: .any)["holeCards"]
        XCTAssertTrue(cards.waitForExistence(timeout: 10), "hole cards not shown")
        XCTAssertEqual(cards.label, "Your cards, hidden")
    }

    func testChipCountsUseTheEnglishFormat() {
        let app = XCUIApplication.launched(debugTable: true, stop: "turn")
        app.waitForTableStop("turn")
        let count = app.descendants(matching: .any).matching(NSPredicate(format: "label CONTAINS %@", "1,000")).firstMatch
        XCTAssertTrue(count.waitForExistence(timeout: 10), "no chip count reads 1,000")
    }
}
```

- [ ] **Step 2: Run the UI test command.** Expected: `testHiddenHoleCardsReadAsHidden` FAILS (no identifier `holeCards`); `waitForTableStop` must already exist for it to compile.
- [ ] **Step 3: Add `.accessibilityIdentifier("holeCards")`** to `HoleCardsView`, next to its `accessibilityLabel`.
- [ ] **Step 4: Run the UI test command.** Expected: all UI tests pass. If the simulator shows a local-network alert, handle it with `addUIInterruptionMonitor` in `launched`, and say so in the report.

### Task 3: Theme sweep with accessibility audit and screenshots

**Implementer:** opus high (judgment on audit findings and flake avoidance).

**Files:**

- Create: `App/UITests/ThemeSweep.swift` (settings helper, sweep, audit, screenshot)
- Create: `App/UITests/KnownAuditIssues.swift` (ignore list)
- Create: `App/UITests/SweepTests.swift`

**Interfaces:**

- Consumes: `XCUIApplication.launched(…)` (Task 1), `waitForTableStop(_:timeout:)` (Task 2).
- Produces: `extension XCUIApplication { func sweepThemes(screen: String, openSettings: () -> Void) }`. For each theme label `Felt`, `Neon`, `Rubin`, `Royal` × `Light`, `Dark`, it opens the Settings sheet through `openSettings`, picks the theme in the "Theme" picker and the segment in the "Brightness" picker, asserts the picker shows the picked theme, audits and photographs the sheet as `settings-<theme>-<brightness>`, taps "Done", then audits and photographs the screen as `<screen>-<theme>-<brightness>`. `<theme>` and `<brightness>` are the raw values: `felt`, `neon`, `ruby`, `royal`; `light`, `dark`.
- Produces: `func audit(_ app: XCUIApplication)`, which runs `app.performAccessibilityAudit()` with a handler that returns `KnownAuditIssues.ignores(issue)`.
- Produces: `struct KnownAuditIssue { let type: XCUIAccessibilityAuditType; let element: String; let issue: Int }` and `enum KnownAuditIssues { static let all: [KnownAuditIssue]; static func ignores(_ issue: XCUIAccessibilityAuditIssue) -> Bool }`. `element` matches the element's identifier or label exactly; `issue` is the GitHub issue number.
- Screenshots are `XCTAttachment(screenshot:)` with `lifetime = .keepAlways` and the name above.

- [ ] **Step 1: Write the sweep tests** in `SweepTests.swift`:
  - `testStartScreenWithASavedGame`: launch with `debugTable: true, stop: "lobby"`, terminate, launch plain; wait for the "Resume game" button; audit and attach `start-saved-game`.
  - `testStartScreenSweep`: launch plain; tap "Discard" if a saved game is offered and wait until "Resume game" is gone; `sweepThemes(screen: "start")`, opening settings with the "Settings" toolbar button.
  - `testTurnTableSweep`: launch with `debugTable: true, stop: "turn"`; `waitForTableStop("turn")`; `sweepThemes(screen: "table-turn")`, opening settings through the "Table" menu, then "Settings".
  - `testPayoutTableSweep`: launch with `debugTable: true, stop: "payout", digitalCards: true, fourColorDeck: true`; `waitForTableStop("payout")`; `sweepThemes(screen: "table-payout")`.
- [ ] **Step 2: Run the UI test command with an empty `KnownAuditIssues.all`.** Expected: the sweeps run through all 8 combinations; audit failures are today's findings. A failure of any other kind (picker not found, stop not reached) is a bug in the tests: fix it before going on.
- [ ] **Step 3: Hand the findings to the controller.** Group the audit findings by audit type and element across all themes and brightnesses. Write each group to the report: audit type, element identifier or label, screens and combinations, the audit's description. Report NEEDS_CONTEXT with the group count. The controller files one issue per group (labels `deferred`, `app`, `accessibility`) and sends back the numbers.
- [ ] **Step 4: Fill `KnownAuditIssues.all`** with one entry per group and its issue number. Run the UI test command. Expected: all UI tests pass. Then run `-only-testing:PokerChipCaseUITests/SweepTests/testTurnTableSweep` followed by `-only-testing:PokerChipCaseUITests/SweepTests/testStartScreenSweep`. Expected: both pass; the second starts with a saved game and discards it.
- [ ] **Step 5: Export and check the screenshots.** Run the export command from Global Constraints. Expected: 49 PNGs (`start-saved-game`, 8 × `start`, 8 × `table-turn`, 8 × `table-payout`, 24 × `settings`), each showing the theme and brightness its name says. Report the full run's duration; expected: under 5 minutes.
- [ ] **Step 6: Commit:** `test(app): theme sweep with accessibility audit and screenshots`
